# 首次启动与新手引导

> 状态：📝 草案
> 创建日期：2026-10-20
> Feature Key：10202150_ONBOARDING

## 需求背景（1-3 句）

新用户第一次打开 Bee Press 时，看到的是六个专业名词组成的空操作台或一个技术错误，既不知道 Bee Press 和 DSH 的关系，也不知道下一步点哪里。目标是把「选项目 → 确认技术栈 → 看到运行中的原型」压成一条不需要解释的路径，失败时给出可执行的修复动作。

## 待决清单（定稿用 · 只看这一节就够）

### A · 需要你拍板

| # | 要定什么 | 我的建议 | 备选 | 你的结论 |
|---|---------|---------|------|---------|
| A1 | 引导卡是否也在桌面首屏出现一次 | 只在操作台出现，桌面首屏保持单一「选择项目」主行动 | 首屏也加三步引导 |  |
| A2 | 跳过引导后能否从帮助入口重新打开 | 可以，帮助面板放「重新显示引导」 | 跳过即永久收起 |  |
| A3 | 检测不到技术栈时的默认动作 | 引导用户手动选择，不猜 | 默认沿用项目现状 |  |

### B · 需要拉研发确认

| # | 要问什么 | 为什么重要 | 确认结果 |
|---|---------|-----------|---------|
| B1 | 依赖安装最长允许多久（当前 5 分钟） | 超时会让大项目误判失败 |  |

## 验收标准

### 功能验收（能用）

1. 原型不可运行时出现三步引导卡，而不是只有错误文案。
2. 「采用检测结果」写入基线并持久化。
3. 创建需求件套后卡片变为完成态，目录真实存在。
4. 缺依赖时可一键安装并启动原型。

### 体验验收（好用）

1. 每步只有一句解释和一个主按钮，不需要读文档。
2. 失败时至少有重试、安装、切换工作区三个出口。
3. 跳过与恢复路径明确，用户不会被引导卡困住。
