TUS v1.0.0 · 工具型产品 UI 规范

让 agent 不能写错
而不是提醒它写对

这套规范的每一行，都是为了让 coding agent 在迭代中没有发挥空间。颜色、间距、圆角、动效全部收敛为令牌；边界、无障碍、容错全部收敛为硬规则。规范不是文档，是可执行的门禁。

规则 58 条 决策树 5 棵 组件配方 8 个 门禁项 45 项
01

设计立场：一条原理，四个推论

规范里的所有规则都服务于同一句话。理解它，才能在规则未覆盖的地方做出正确判断。

◆ 第一性原理

工具型产品的设计目标，是降低「长期使用」的认知负担，而不是制造「第一眼」的惊艳。任何设计决策，问一句"用户连续用 8 小时后，这个决定还成立吗？"——不成立的，就是消费级审美，不是工具级设计。

👁

长时间注视

视觉必须低刺激。低饱和、低对比层级、暖中性底色、无大面积高亮。

→ 低刺激
🔁

高频重复

交互必须可预测。固定位置、固定动效、固定反馈，不搞惊喜。

→ 可预测
📊

信息密度高

层级靠结构而非装饰。用明度差与留白分层，不用边框堆叠。

→ 结构分层
⌨️

键盘优先

焦点与快捷键是一等公民。全键盘可达、焦点可见。

→ 可键盘

不变量 vs 可变量

这是本规范能被"通用化"的关键。换品牌时只改可变量，不变量永不改动。

类别内容能否替换
不变量四层表面分层逻辑 · 单闭合边框 · 圆角语义分级 · 动效四类分工 · 状态机 · 边界守卫 · 无障碍基线不可改
可变量强调色 · 中性色温度 · 字体族 · 圆角性格 · 动效性格可替换

不是所有交互都该用同一种动画。阻尼比 ζ 决定运动的性格——利落、果冻、沉稳，还是绝对咬合。agent 只能选，不能调。

利落归位，几乎无多余弹跳。用于按钮点击、Tab 切换、hover 这类高频微交互。

05

五棵决策树

agent 遇到需要"判断"的地方，必须走决策树取唯一分支。不允许自由发挥。

5.1 区分两个区域 → 用什么

需要区分两个视觉区域 │ ├─ 父子层级（外壳 vs 内容）？ │ └─ 用 surface 明度差 │ ├─ 同层并列（卡片 A vs 卡片 B）？ │ ├─ 有间距 → 只用间距，不加任何边框 │ └─ 无间距 → 1px 单向细线 │ ├─ 独立可交互实体（弹窗、代码块、可拖拽卡片）？ │ └─ 允许 1 层闭合边框 + 阴影 │ └─ 在已有边框的容器内部？ └─ 禁止边框，改 hover 底色 / 填充

5.2 动效 → 哪套弹簧

动效场景 │ ├─ 高频微交互（点击、Tab、开关、hover）？ → snappy ├─ 情绪反馈（成功、点赞、徽章出现）？ → bouncy ├─ 大尺度空间变化（弹窗、折叠、分栏）？ → gentle ├─ 精确落位（拖拽吸附、碰撞、贴边）？ → heavySnap └─ 只是透明度 / 颜色变化？ → 120ms + ease-out

5.3 异步操作 → 展示什么状态

发起异步操作 │ ├─ 预计 < 100ms → 不展示 loading（避免闪烁） ├─ 预计 100ms–1s → 局部骨架 / 按钮内 spinner，禁用重复提交 ├─ 预计 1s–10s → 骨架屏 + 阶段文案 ├─ 预计 > 10s / 流式 → 流式输出 + 进度 + 取消按钮 └─ 失败 → 错误三要素 + 重试 + 保留用户输入

5.4 响应式 → 哪种查询

需要响应式适配 │ ├─ 调整的是页面级骨架（侧栏宽度、整体栅格）？ │ └─ 用 @media（视口断点） │ └─ 调整的是组件内部布局（卡片列数、按钮文字显隐）？ └─ 必须用 @container └─ 根元素须声明 container-type: inline-size

5.5 圆角 → 取多少

组件类型 │ ├─ 徽章 / 角标 / 复选框 → 2px ├─ 快捷键键帽 → 4px ├─ 极小按钮（≤24px） → 6px ├─ 标准按钮 / 输入框 → 8px ├─ 卡片 / 附件磁贴 → 10px ├─ 代码块 / 大卡片 → 12px ├─ 弹窗 / 抽屉 → 16px ├─ 消息气泡 → 18px ├─ 大输入框（Composer） → 20px └─ 分段控件 / 头像 → 999px ⚠ 嵌套时必须校验：R_outer = R_inner + padding
