# 原型部署

## 前提

- 原型已能本地构建；
- 目标环境已由项目配置，**不要把域名、账号、token 写进仓库**；
- 已确认这次是预览还是正式发布，以及访问范围。

## 1. 构建与预检

```bash
npm run build
npx builderharness preflight
```

预检失败时先修，不要带泄漏产物部署。至少确认：

- 生产包不包含评审/内容工具和源码坐标；
- 没有 `.env`、真实用户数据、内部域名；
- 静态路由在目标托管上有 fallback，或使用 hash 路由。

## 2. 计划

```bash
# 具体命令由宿主配置的部署 CLI 决定
<deploy-cli> --dir dist --dry-run
```

把目标、版本、访问范围、回滚方式写进计划，让人确认后再执行。

## 3. 部署

```bash
<deploy-cli> --dir dist
```

只用构建产物目录；不要上传整个仓库。

## 4. 验证

- 打开返回的 URL，走主路径；
- 确认线上首页的构建版本/时间与本次一致；
- 检查静态资源 404、深链 fallback、缓存头；
- 把预览链接写回需求或发布记录。

## 5. 边界

- 不把部署凭证写入 Skill、脚本或日志。
- 失败时保留本地 `dist/`，先报告失败原因，不静默重试到线上。
- 访问范围默认最小；公开链接必须显式确认。
